# План перехода CI на штатную Debian-упаковку Dante

Статус: изменения CI/CD и Debian-упаковки реализованы. Выполненные проверки
и ограничения локальной валидации перечислены в [TDD-отчёте](debian-package-compatibility.tdd.md).

## Цель и границы

Обновление штатного `dante-server` должно сохранять системный интерфейс пакета:

- бинарник `/usr/sbin/danted`;
- службу `danted.service` и штатный vendor-unit `/lib/systemd/system/danted.service`;
- конфиг `/etc/danted.conf`, включая пользовательское содержимое и права;
- штатное обслуживание PID-файла и службы;
- обязательную поддержку PAM и libwrap.

Собирать отдельные пакеты для Ubuntu 22.04 и Debian 12, на amd64 и arm64. RPM и macOS сохраняют текущую упаковку. Автоматическая миграция ранее выпущенных кастомных пакетов с `sockd.service` не входит в задачу.

Statistics API остаётся в бинарнике, но по умолчанию выключен. Штатный юнит не получает параметр `-S`; включение API описывается через административный systemd override.

## Debian-упаковка

1. Актуализировать корневой `debian/`, используя упаковку Ubuntu `1.4.2+dfsg-7build4` и соответствующую упаковку Debian 12 как проверенные образцы. Зафиксировать происхождение и контрольные суммы исходных материалов; сохранить лицензионные уведомления. Старые патчи проверить на применимость к текущему Dante, исключить уже применённые и несовместимые.

2. Сделать `debian/rules` единственным источником правил DEB-сборки. Использовать debhelper compat 12, штатные механизмы зависимостей, conffiles, SysV init и systemd. Сохранить конфиги и содержимое юнита соответствующего дистрибутивного образца; не подменять их текущими CI-шаблонами `sockd`.

3. Сохранить дистрибутивный подход: исходный executable может собираться как `sockd`, но пакет устанавливает его как `danted`. Согласовать compiled-in пути, man-страницы и install-манифесты. Пакет не должен устанавливать `/usr/sbin/sockd`, `/etc/sockd.conf` или `sockd.service`.

4. Добавить обязательные зависимости сборки PAM/libwrap и убрать их отключение для DEB. Оставить `--without-gssapi`, как в проверенном Ubuntu-образце. После configure проверять реально включённые возможности: отсутствие PAM или libwrap завершает сборку ошибкой. Не заменять существующие PAM-политики хоста.

5. Сохранять полный набор бинарных пакетов, определённый актуализированным `debian/control`, при сборке. В пользовательский release публиковать только `dante-server`; остальные результаты сохранять как CI-артефакты для диагностики.

## Изменения CI и release

- Экспортировать из одного Git-коммита исходники `dante/` и корневой `debian/`. В рабочем каталоге сборки размещать `debian/` рядом с `configure`; подготовку выполнять вне checkout.
- DEB-ветка устанавливает `Build-Depends` и вызывает `dpkg-buildpackage -b -us -uc`. Удалить создание DEB payload и maintainer scripts из `package.py`; сохранить его RPM/macOS-ветки.
- Использовать закреплённые образы целевых ОС. Версии DEB: `<upstream>-<revision>+ubuntu22.04` и `<upstream>-<revision>+debian12`. Сохранить существующее образование preview-revision; для выпуска исправления использовать новую release-revision.
- Расширить матрицу, metadata и проверку release-артефактов на четыре DEB-цели. Различать общую версию релиза и фактическую версию конкретного DEB; проверять последнюю по содержимому пакета.
- Сохранять configure/build logs, `danted -vv`, `.buildinfo`, `.changes`, зависимости и контрольные суммы. Публикация остаётся созданием draft release.
- Все четыре DEB-цели проходят проверки на PR и release. Обновление проверяется в изолированных VM целевой ОС с systemd как PID 1; использовать QEMU, с TCG как доступным резервным режимом.

## Проверки и критерии приёмки

### Сборка и содержимое

- Существующие C-тесты statistics API, Python-тесты упаковки, ShellCheck, actionlint и Lintian.
- Проверка имён, путей, conffiles, зависимостей, man-страниц и юнита внутри готового DEB.
- `danted -vv` содержит PAM/libwrap; для Ubuntu сохраняются возможности, показанные пользователем: `libwrap mon-data mon-disconnect pam preload sess2`. Списки socket options не сравниваются побайтно между платформами.

### Реальное обновление

В каждой VM установить штатный пакет, настроить локальный SOCKS listener и тестовую PAM-политику, затем обновить готовым DEB.

Проверить:

- содержимое, владельца и права рабочего конфига до/после;
- сохранность пользовательского systemd override;
- работу службы после обновления и перезагрузки VM;
- сохранение enabled/disabled и masked состояний в отдельных сценариях;
- успешную PAM-аутентификацию, отказ неверному паролю и отказ по account policy;
- TCP/UDP-проксирование и отсутствие второй службы `sockd`;
- корректное поведение при существующем obsolete `/etc/sockd.conf`: его содержимое не используется вместо `/etc/danted.conf`.

Отдельно проверить чистую установку и statistics API через документированный override с корректными правами каталога сокета, включая непривилегированного пользователя, отличного от `nobody`.

### Откат

Проверить возврат к сохранённому штатному DEB с исходным конфигом и восстановлением службы. Обновление допускает перезапуск процесса и разрыв текущих соединений; непрерывность сессий не обещается.

## Выполнение и документация

Оркестратор фиксирует архитектуру и критерии, затем делегирует последовательно: Debian-упаковку, интеграцию CI/release, интеграционные проверки. Для пересекающихся файлов назначается один исполнитель. После интеграции отдельный read-only reviewer проверяет совместимость обновления; оркестратор выполняет итоговую проверку.

Документация описывает выбор пакета по ОС/архитектуре, обновление, включение API и откат. Для старого кастомного пакета предусматривается отдельная ручная процедура с резервной копией и явным выбором конфига; автоматическое объединение двух конфигураций исключается.
